# JarenJS Website

The official GitHub Pages site for Jaren — a showcase for the complete toolchain: the JSON Schema
validating compiler and the addressing/query/transformation stack around it (JSON Pointer, JSONPath,
the Jaren JSON Query language, JSLT stylesheets, the XQuery front-end, formats and form generation).

## What's on it

- **Home** — the full-suite pitch: conformance proof strip (JSON-Schema-Test-Suite, JSONPath CTS,
  W3C QT3), a per-engine code showcase, the honest speed table, the LLM story, the package grid.
- **Playground** — every engine live in the browser, no server, no eval:
  - *JSON Schema*: compile + validate per keystroke, with the `@jarenjs/forms` generated-form tab
  - *JSONPath*: values and RFC 9535 normalized paths per keystroke
  - *JSON Pointer*: absolute + relative pointers (the `$data` hot path)
  - *JSON Query*: FLWOR/joins/grouping, externals, `$valid` with a real compiled schema
  - *JSLT*: stylesheets with the `=== input` shared-identity badge
  - *XQuery*: text → emitted query document → result, in one pipeline
- **Benchmarks** — five suites, each against the strongest competitor on its own turf, with
  drill-down to **every individual test case** (search, sort, winner filters, per-test ratio bars):
  - JSON Schema vs Ajv (per-test, the official suite)
  - JSONPath vs json-p3 (all 456 timed CTS queries + synthetic scale scenarios)
  - JSON Query vs fontoxpath/JSONata (scenario matrix with the actual programs viewable)
  - JSLT vs hand-written JS/JSONata (including the honest "native wins transforms" analysis)
  - JSON Pointer vs the legacy resolver and the `jsonpointer` npm package
- **Docs** — the whole suite in one pass, each section linking the deeper spec in the repo.
- **Examples** — copy-paste patterns per engine, mirrored by the playground example chips.

## Benchmark data pipeline

The Benchmarks page reads static JSON from `public/benchmarks/` (one file per suite + `meta.json`),
generated by [`benchmark/website-data.js`](../../benchmark/website-data.js), which runs every
benchmark tool in the repository with `--output json` and assembles the site files:

```bash
# from this package
npm run benchmark:generate   # full run (validator at 1000 iterations) — use before deploying
npm run benchmark:quick      # fast smoke run for wiring/dev — numbers are NOT publishable

# or from the repository root
node benchmark/website-data.js [--quick] [--iterations N] [--skip suite,suite]
```

Generate on a quiet machine: the suites measure real timings. The QT3 scorecard needs the
`benchmark/qt3tests` submodule converted once (`npm run qt3:convert`); without it the scorecard
is omitted and the site simply hides it.

Convention: in the generated files `ratio` is always **competitor-time ÷ Jaren-time**, so ratios
above 1 read "Jaren is N× faster" everywhere (note: `profiler.js` itself uses the inverse).

## Tech stack

- **Build**: Vite 6 · **UI**: React 19 + Tailwind CSS 4 · **Icons**: Lucide
- **Engines**: `@jarenjs/validate`, `@jarenjs/json`, `@jarenjs/formats`, `@jarenjs/forms`,
  `@jarenjs/refs` — imported as workspace sources and bundled into the `jaren` chunk
- **Testing**: Vitest + React Testing Library

## Development

```bash
npm install            # from the repo root (workspaces)
npm run dev            # start the dev server
npm run build          # production build
npm run preview        # serve the production build
npm run lint           # eslint
npm test               # vitest
npm run deploy         # build + push dist/ to the gh-pages branch
```

`predeploy` runs the full benchmark generation followed by the build, so a deploy always ships
fresh, full-iteration numbers.

## Project structure

```
src/
├── components/
│   ├── ui/           # primitives (Button, Card, Tabs, ...)
│   ├── layout/       # Header, Footer, ErrorBoundary
│   ├── demo/         # the playground engines (one file per engine) + shared chrome
│   ├── benchmarks/   # the benchmark drill-downs (one file per suite) + shared marks
│   └── features/     # DraftSupport
├── hooks/            # useJarenValidator, useBenchmarkData (per-suite file loader)
├── lib/              # utils, examples (validator), playgroundExamples (all engines)
├── pages/            # Home, Playground, Benchmarks, Documentation, Examples
└── main.jsx
```

## GitHub Pages

The base URL is `/jarenjs/` (see `vite.config.js`); routing is hash-based so deep links like
`#/benchmarks?suite=jslt` and `#/playground?engine=xquery` work on Pages.
